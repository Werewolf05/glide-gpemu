Scheduler validation

Corrected, paired comparison using the same arrivals for every policy.

Tesla M40 · Poisson 40 requests/s · 15 seconds · batch sizes 1, 8, 16, 326 models · HASP aging: 5 seconds

Measured trade-off: Across 30 seeds, HASP lowered mean P95 latency versus SJF by 1,924.9 ms (paired 95% CI: 1,757.3–2,092.5 ms lower) and raised the Jain latency index by 0.080. Mean latency increased by 63.7 ms (95% CI: 58.9–68.5 ms higher); throughput was unchanged. FIFO had lower P95 than HASP in this run.

Reading the numbers

A quick guide to the terms used in the files.

Average latency

Average time from request arrival to completion, including service time. Values are in milliseconds.

P95 latency

95% of requests completed within this time; the slowest 5% took longer. It highlights tail delays.

Requests / sec

Throughput: the number of requests completed per second in the experiment.

Jain latency index

This project computes Jain's index on raw latencies. Closer to 1 means more equal latency values, not necessarily shorter latency.

FIFO, SJF, HASP

FIFO serves requests in arrival order. SJF prioritizes shorter jobs. HASP is the project's custom scheduler.

Compute and memory

Benchmark compute is emulated processing time. Memory is an estimated model/batch footprint, not a measurement of your machine's live GPU memory.
